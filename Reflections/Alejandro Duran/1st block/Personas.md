# Personas

## Claim

The "Personas" method gives us a better understand about our users, their needs and specific behaviors, and with this way we prevent the creation of users called "elastic users" that means a user created with some conveniences of different stakeholders.

## Data

When we discuss about behaviors, we can see a great digital issues between administrative staff and manual workers, an example could be a manual worker that don't have a personal computer and never has been a closer encounter with this technology.

## Warrant

The using of tools like interviews and shadowing, allowed us to find the why behind the user actions, as their dependence on personal interact and help modules, caused by some common issues that still happen ass the loss of institutional passwords.

## Backing

This methodology is based in the work of Nielsen that propose that personas must be based on the empiric observation of human behaviors to still be valid and useful, personas should not be fictional stereotypes or assumptions created without evidence, a validity evidence is that they must be created by systematic user research.

## Qualifier

Personas are only effective if they are constantly updated, if we use personas as an incorruptible and constant bible, we lose relevance of our personas, we need to refresh data and constantly research new valid information.

## Rebuttal

While some designers think that demographic data like age or location are enough, personas focus on objectives, making sure that the application architecture supports different levels of digital literacy.

## Example

The persona that we construct for our simulation, make a change on how we see the login. Instead of a mandatory Microsoft login, we will include an alternative login using an Employee ID trough a message, ensuring the app is inclusive for users who do not regularly check institutional email.
