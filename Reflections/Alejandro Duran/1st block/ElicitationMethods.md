# Elicitation Methods

## Claim

Elicitation methods are essential to capture the user requirements, but their success depend on how strict the team follow the techniques established, as contextual investigation and scenario mapping.

## Data

Our team implement elicitation through scenario mapping, creating narrative descriptions of how a user reacts when a beneficiary gets sick and how they react depende on the description of different types of users.

## Warrant

Implementing these techniques, we reduce the gap between the manual system and our digital propuse, and give us a bridge to that facilitates the transition for our users.

## Backing

The Nielsen's usability heuristics, specifically when he said, "Match between system and the real world", support the idea that systems must talk the user language instead of use system oriented terms that made a most difficult understanding for people.

## Qualifier

The technique is only as good as the analysis, if we have a clear method to synthesize data, but if we don't have this, the process can become in a bottleneck.

## Rebuttal

You might think that is enough asking what the user wants, but observation often revels bottlenecks behaviors that the own users don't even notice.

## Example

On the repository of our project, the user research artifact shows that we could improve the technique using diagrams to process the collected data more quickly and that during execution we see that some questions of the interview were to technicisms, which increased the user load.
