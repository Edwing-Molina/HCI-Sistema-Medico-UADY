### 2.2 Accessibility in Login

#### Interface Scaling for Older Adults

**General Observation:** The entire group was able to view text fields and labels at the default size without readability issues.

- **Grazielita:** Perfect visibility; prefers interfaces with few large and easy-to-find buttons
- **Elda:** Perfect visibility; maintained standard alignment
- **Verónica:** Does not use OS scaling, but prefers larger text; required additional visual concentration
- **Alejandro:** No active scaling, but prefers slightly larger text; able to read without assistance

**Implication:** The current interface is readable for this age range, but there is room to improve the visual experience for users who prefer larger text.

#### Color-Independent Error Messages

All participants understood the error messages without relying solely on color coding:

- They identified authentication alerts through text
- They understood security warnings
- No confusion caused by color differences

**Conclusion:** Color coding complemented by text works well for this group.

#### Keyboard Navigation

**Variable Performance:**

- **Grazielita:** CRITICAL – Multiple failures with the virtual keyboard; frustration after several attempts; required evaluator assistance
  - *Root cause:* Difficulty entering complex password characters on the virtual keyboard
  - *Impact:* Severe entry barrier; the user stated she depends on family members for similar tasks

- **Elda:** Completed successfully; required extended time to enter credentials
  - *Root cause:* Needed to erase and rewrite her password

- **Verónica:** Completed successfully; longer processing due to password retry
  - *Root cause:* Initial typing mistake

- **Alejandro:** Completed without errors; smooth flow through SSO

**Critical Observation:** The virtual keyboard is a significant friction point for users with low digital proficiency and complex passwords. Grazielita, in particular, demonstrated that this is a substantial obstacle.

# 4. Common Patterns Identified in the Group

## 4.1 Shared Positive Characteristics

### 1. Institutional Branding Trust

All participants demonstrated high trust when recognizing the UADY logo and Microsoft SSO integration. This is a **very strong satisfaction factor** that compensates for friction in other areas.

### 2. Understanding Errors Without Color

The group does not rely exclusively on the color red to identify errors. Text messages function effectively, suggesting that the current accessibility implementation is adequate for this age range.

### 3. Patience with Loading States

No participant repeatedly clicked buttons during loading. This is a **positive indicator** that the interface communicates processing states effectively.

### 4. Understanding Business Restrictions

When the application blocked past months, all participants accepted the restrictions without confusion. This indicates that **business rules are intuitive**.

### 5. Efficiency in Appointments

The appointments module is significantly more efficient than the login module. This suggests that **the scheduling flow is well designed** for this demographic group.

---

## 4.2 Shared Problematic Characteristics

### 1. Initial Exploration Difficulty

Grazielita and Elda showed reluctance to explore the interface. They expressed fear of clicking unfamiliar buttons.

**Implication:** This group requires stronger **initial confirmation and guidance** to build confidence.

### 2. Friction in Login

The login module was significantly more problematic than appointments:

- **Complex virtual keyboard:** Grazielita experienced repeated failures
- **Complex passwords:** Character combinations created friction
- **Multiple attempts required patience:** 3+ attempts caused visible frustration

### 3. Digital Competency Gap

Two participants (Grazielita and Elda) explicitly mentioned family dependence. This indicates that **not all users within this group possess the same level of autonomy**. The interface must accommodate users with extremely low competency levels.

### 4. Navigational Friction in Appointments

Although appointment booking is efficient, **finding already scheduled appointment details was problematic**:

- Grazielita: 2 cognitive blocks
- Elda: 1 cognitive block
- Verónica: 0 blocks
- Alejandro: 0 blocks

**Implication:** There is an **Information Architecture** issue in the appointment details section for less digitally experienced users.

### 5. Motor Precision Problems (Limited to Grazielita)

Only Grazielita showed 5 accidental clicks. This may be related to:

- Post-shift fatigue
- Lower touchscreen familiarity
- Age-related motor precision limitations

# 10. Final Notes

This demographic group (45–55 years old, UADY administrative staff) represents valuable institutional users. Their lower average digital competency **is not a flaw; it is a reality among older staff members**.

The application should be designed empathetically for this group. The appointments module demonstrates that **highly usable interfaces are possible** for this age range. The login module demonstrates where technical complexity (virtual keyboard, complex passwords) creates unnecessary friction.
